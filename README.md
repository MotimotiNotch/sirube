# Sirube

[![ko-fi](https://ko-fi.com/img/githubbutton_sm.svg)](https://ko-fi.com/motimotinotch)

> 目的から「それには何が必要か」を辿ると、末端に今日できることが現れる。半年空けても、道は残っている。

長期プロジェクト向けの、**中断に強い**タスク管理ツール。

名前は日本語の「**道しるべ**」から。綴りは訓令式ローマ字。

---

## 何が違うのか

普通のタスク管理は、**すでにあるタスク同士に後から依存を貼る**。Sirube は逆で、**目的から出発して「それには何が必要か」を再帰的に下ろす**。タスクは分解によって初めて生まれる。

```text
引っ越しをする
  ├─ には → 引っ越し先の家が必要
  │            └─ には → 不動産に行く必要がある
  └─ には → お金が必要
```

そして**分解して出来た木が、そのまま状態機械として動く**。末端まで下りると「今日できること」が現れ、それを叩くと前提が自動で埋まって上まで伝わる。

- アウトライナーやマインドマップは分解できるが、出来た木は動かない
- 依存タスク管理は「今やれるもの」を出せるが、目的ひとつから木を作る流れが無い

その交点を狙っている。

---

## 中断に強いということ

半年放置して開いても、「今どこにいて、次に何をすればいいか」がグラフから再構成される。手で next action を決め直す必要がない。

- **達成1つで前提が埋まる** — ノードを1つ達成にすれば `requires` 連鎖を遡って前提も全部達成になる（押したもの以外が書き換わるときは、書く前に一覧で見せる）。数週間ぶりでも状態更新に時間がかからない
- **検索が完全一致ゲームでない** — 一致したノードの**隣接も一緒に出る**ので、「CI/CD」で引けば「手順書」も浮かぶ。単語を思い出せなくても辿り着ける
- **詰まっている理由が出る** — 待ち合って一周しているせいで何も動けないとき、その一周が「今やれること」の上に出る

## 使いはじめる

画面の一つ一つの説明は、アプリのヘッダーの **「使い方」**（中身は [`docs/manual.md`](docs/manual.md) と同じ）にある。ここは入れてから最初の一周まで。

### 1. 入れる

[Releases](https://github.com/MotimotiNotch/sirube/releases) から Windows 向けインストーラ（`Sirube_0.2.0_x64-setup.exe` / 約 2MB）を落として実行する。

> インストール時に **「Windows によって PC が保護されました」** と出る。コード署名証明書を取っていないだけで、警告の中身は「発行元が確認できない」。**詳細情報 → 実行** で進める。

外部通信もアカウントも無い。入れたら終わり。

<details>
<summary>自分でビルドする場合</summary>

```
bun install
bun run release        # 要 MSVC。src-tauri/target/release/bundle/nsis/ に出る
```

</details>

### 2. 最初に開くフォルダを決める

初回起動でフォルダを聞かれる。**空のフォルダで構わない**——中に `nodes/` が作られ、データは全部そこで完結する。

Obsidian の Vault と同じ考え方で、**フォルダごと Git で持ち歩ける**。既存の Obsidian Vault の中に置いてもいい。

### 3. 目的を1つ作る

左の「目的」の横の **＋**。達成したいことを1つだけ書く（`引っ越す` `確定申告` `ポートフォリオを公開する`）。

**この時点では何も分解しなくていい。** 分解は後から足せる。

### 4. 「それには何が必要か」を書き下す

作った目的を開いて、右の **「分解する」**。モーダルの見出しがそのまま問いになっている:

> 「引っ越す」には何が必要？

1行に1つ書く。`Ctrl+Enter` で確定。

```
引っ越し先の家
お金を貯める
不動産に行く
```

**出てきたものをまた開いて、同じ問いを繰り返す。** これがこのツールの中心で、ここを下ろしていくと末端に「今日できること」が現れる。

モーダルの **「中身」** タブに切り替えると、問いが「「引っ越す」は何でできている？」に変わる。全部揃えばそれ自体にやることが残らないもの（担当分・部品・機能のまとまり）はこちらで足す。

一気に書き下したいときは、左の「目的」の横の **＋** で開く画面の **「まとめて書く」** タブに DSL を貼る（グラフの余白を右クリックしても開ける）:

```
引っ越す -> 引っ越し先の家 -> 不動産に行く, 引っ越す -> お金を貯める
```

### 5. 末端を叩く

左上の **「今やれること」** に、前提が全部揃ったものだけが出る。1つ達成にすると、**前提が遡って全部達成になり**、上まで伝わる。

数週間ぶりに開いても、状態を手で更新し直す必要がない。

### 6. 半年後

開くだけ。「今やれること」がそのまま出る。待ち合って一周しているせいで空なら、**その一周が一覧の上に出る**。

何を動かしていたか思い出せないときは、左の **「最近の変更」**。書き換わった新しい順に30件並ぶ（ファイルの更新時刻なので、連動して書き換わったものも入る）。ノードの詳細パネルにも作成日と更新日が出る。

### データはどこにあるか

選んだフォルダの中だけ。

| | |
| --- | --- |
| `nodes/*.md` | **これが全部。** 1ノード1ファイル |
| `00_Sirube_MOC.md` / `goals/` / `90_達成済み.md` | Sirube が作る入口。**Obsidian で開く用**（スマホからも読める）。消しても作り直される |
| `AGENTS.md` | エージェント向けの仕様書。同上 |

`nodes/` 以外は生成物なので、編集しても次の保存で上書きされる。

## AI に読み書きさせる

AI 連携機能は**アプリに実装していない**。データが Markdown なので、Claude Code や Cursor に `nodes/` を直接触らせれば、それがそのまま連携になる。API キーも設定も要らない。

### 1. エージェントに場所を教える

アプリは起動のたびに、今開いている vault のパスを書き出している:

```
%LOCALAPPDATA%\jp.motimotinotch.sirube\vault-path.txt
```

**このファイルの場所だけは、最初に人から伝える必要がある。** 「`%LOCALAPPDATA%\jp.motimotinotch.sirube\vault-path.txt` を見て」と言えば、あとはエージェントが vault まで辿り着く。vault を別のフォルダへ移しても伝える内容は変わらないのが、フォルダを直接渡すのとの違い（直接渡してもいいが、移すたびに言い直すことになる）。

毎回言うのが面倒なら、エージェント側の設定ファイル——Claude Code なら `CLAUDE.md`——にこの1行を書いておけばいい。

**アプリはこれを読まない。** 書き換えても開く vault は変わらない（切り替えはアプリから）。外へ向けて書くだけの掲示板で、正はアプリの中にある。

### 2. 仕様を読ませる

**vault の中に `AGENTS.md` が置いてある**（アプリが起動のたびに書き出す）。エージェントに「vault の `AGENTS.md` を読んで」と言えばそれで済む。

**形式そのものではなく、ファイルを見ても分からないこと**が書いてある——`requires` と `contains` の判別基準、参照は名前で書いてよいこと、`id` と `number` は書かないこと、待ち合い（循環）の扱い。

データと同じフォルダにあるので、**git で別マシンへ持っていっても、vault だけ渡しても付いてくる**。アプリのバージョンと必ず一致する。

### 3. 頼めること

- **分解の一括投入。** 「この目的を分解して」と言えば DSL かノードを書き下ろす。名前で参照を書けるので、id を調べる往復が要らない
- **棚卸し。** 「この目的の下で止まっているものは？」「待ち合って一周しているところは？」
- **メモの整理。** 本文は普通の Markdown なので、そのまま書き足せる

### 4. 頼まないほうがいいこと

**`satisfied` の直接書き換え。** ファイルを直接 `true` にするとカスケードが走らず、前提が未達のまま残る。**達成はアプリで叩く。**

（やってしまっても壊れはしない。ヘッダーの「自動解決」が変更時刻を見て辻褄を合わせる）

### 5. 書いた後

アプリはフォルダを監視しているので、**エージェントが書いたものは自動で画面に出る**。

### 書き込みの入口は2つに絞ることを勧める

**人間はアプリから、AI はファイルを直接。** Obsidian やエディタで人間も直接書くと、入口が増えて矛盾の出方が散らかる。読むのはどこからでも構わない。

## データはただの Markdown

1ノード = 1ファイル。中身はこれだけ。

```markdown
---
name: 確定申告
number: 9
satisfied: false
requires:
  - 01M1DR2XM4BSDZTH8C12FMC0YC  # 領収書整理
contains: []
due: 2027-03-15
---

去年は freee で出した。今年は医療費控除も入れる。
```

ファイル名は意味を持たない ID（ULID）。表示名を `name` に分けてあるので、**改名しても参照は1本も切れない**。`number` は `#9` のように口に出して指すための札で、どちらもアプリが振る。

- **`git diff` が「誰がどのノードを完了したか」そのものになる**。チーム共有は Git に任せる（ツールは Git を握らない）
- **Obsidian でそのまま開ける**。ノード本文が普通のノートになる
- **ツールが死んでもデータは残る**

外部通信もアカウントも無い。全部ローカルのファイル。

## 循環は、エラーではない

「実績を作るには案件が要る。案件を取るには実績が要る」——こういう待ち合いは現実に普通にできる。

Sirube はこれを**「分解が足りない」信号**として扱う。待ち合って一周するのは、1つの名前に2つの違うものが混ざっているサイン。

```text
実績を作る → 案件を取る → 実績を作る          ← 詰まっている

大きい案件を取る → 実績を作る → 小さい案件を1件やる → 知人に声をかける
                                                    ↑ 割ると行動が生まれる
```

なので画面に出るのは「どれかを切ってください」ではなく「**この待ち合いの中に、2つに分かれるノードがあるかもしれません**」。

## 設計

`src/core/` は UI にもファイルシステムにも依存しない純粋なロジック。

| ファイル | 役割 |
| --- | --- |
| `core/model.ts` | データモデル。保存する状態は `satisfied` だけ |
| `core/engine.ts` | 状態導出（4値）・カスケード・循環検出・隣接 |
| `core/dsl.ts` | テキスト DSL と一括追加（前提・中身） |
| `core/search.ts` | 検索＝横断ビュー（同じ機能） |
| `core/reconcile.ts` | 整合性の自動解決（mtime の新しい方を正） |
| `store/frontmatter.ts` | Markdown ⇄ ノード |
| `store/fs.ts` | ファイルアクセスの抽象（Tauri / メモリ） |
| `store/store.ts` | 変更されたノードのファイルだけを書く |

モデルは意図的に最小に保っている。種別・優先度・タグを持たないのは、**同じことを2通りで表現できるようにすると分解の流れが止まる**から。優先度は合流点の入次数が構造として表し、分類はエッジで表現できる。
