# Sirube の使い方

この画面はアプリの中のマニュアルです。上の目次から章へ飛べます。

## 0. 考え方

### 目的から下ろす

Sirube では、タスクを思いついた順に並べません。**目的を1つ置き、「それには何が必要か」を繰り返し問うて下ろしていきます。** タスクは、分解したときに初めて生まれます。

```
引っ越しをする
  ├─ 引っ越し先の家
  │    └─ 不動産に行く
  └─ お金を貯める
```

下ろしきった末端（ここでは「不動産に行く」と「お金を貯める」）が、**今日できること**です。

### 優先度は手で付けない

「今やれること」の一覧は、ここまでに書いた構造から出てきます。

- 必要なものが全部揃ったものだけが「今やれる」になる
- 複数の目的から必要とされているもの（**合流**）は、片付けると一度に複数が進む。一覧では合流の数が出る

優先度の欄や、タグはありません。分解の向きが優先順位の代わりをします。

### 保存するのは「済んだか」だけ

状態として覚えているのは、ノードごとに**達成したかどうか**だけです。「今やれる」「前提待ち」といった状態は、開くたびに構造から計算し直します。

| 状態 | 意味 |
|---|---|
| 今やれる | 必要なものが全部揃っている |
| 前提待ち | まだ揃っていないものがある |
| 達成済み | 済んだ |
| 待ち合って一周している | お互いを待っていて動けない（→ 7. 整える） |

このおかげで、**半年空けて開いても「今どこにいて、次に何をすればいいか」がそのまま出ます。** 次にやることを手で決め直す必要はありません。

### 繋ぎ方は2種類

「何が必要か」には2通りあります。

- **前提**: 揃ったあとも、まだ自分でやることが残る（家もお金も揃っても、引っ越し作業そのものが残る）
- **中身**: 全部揃えば、それで終わり（担当分や部品の集まり）

見分け方と使い分けは「3. 分解する」で説明します。

### データはただのファイル

ノード1つが Markdown ファイル1つです。アプリの外（エディタや Obsidian）からも読めます。詳しくは「8. 渡す」で。

## 1. 画面の見取り図

画面は上のヘッダーと、左・真ん中・右の3列でできています。

| 場所 | 何があるか |
|---|---|
| 上（ヘッダー） | 検索欄、フォルダ名、戻す、自動解決、使い方 |
| 左（サイドバー） | 今やれること、最近の変更、目的の一覧 |
| 真ん中 | 一番上にパンくず、その下に一覧かグラフ |
| 右（詳細パネル） | 選んでいるノードの詳細 |

### ヘッダー

| 部品 | 役割 |
|---|---|
| 検索欄 | 名前と本文から探す。空にすると「今やれること」に戻る（→ 2. 入る） |
| フォルダ名 | 今開いているデータの場所。押すと場所の確認と、別のフォルダを開く口が出る |
| 戻す | 直前の操作を1手だけ戻す。戻せるものがあるときだけ出る（→ 3. 分解する） |
| 自動解決 | 食い違いを直す提案。提案があるときだけ、件数付きで出る（→ 7. 整える） |
| 使い方 | このマニュアル。先頭からチュートリアルをもう一度通せる |

### サイドバー（左）

- **今やれること** — 起動直後の画面。数字は今やれるものの件数
- **最近の変更** — 書き換わった順の一覧。間を空けて開いたときの手がかり
- **目的** — 地図に出ているゴールの一覧。数字は「達成した数／全体」。横の **＋** で新しい目的を作る

### 真ん中

一覧かグラフのどちらかが出ます。

- 一番上の行が**パンくず**。今どこを見ているかと、辿ってきた道。押すとそこへ戻る
- 行の頭の **＋** は「**ここに足す**」。今選んでいるノードの下に足す（→ 3. 分解する）
- 右端の「俯瞰」「地図」「グラフ」で見え方を切り替える（→ 5. 俯瞰する）
- グラフの左下の丸いボタンに、印の見方（凡例）がある

### 詳細パネル（右）

選んでいるノードの詳細です。何も選んでいないときは畳まれています。

- 名前（鉛筆で改名）、番号（`#12`）、状態、進み具合
- **達成にする** / **分解する** のボタン
- **付箋** — ゴールにだけ貼れる色
- **これを待っている** / **属する先** — このノードを必要としている上のノード。押すとそこへ移る。右クリックで「外す」
- **メモ** — 本文。「編集」で書ける
- 作成日と更新日
- **その他** — 地図に出す／地図から外す、削除

### 幅を変える

列の境目はドラッグで幅を変えられます。端まで寄せると畳まれ、ダブルクリックで元の幅に戻ります。

### ノードの番号

ノードにはそれぞれ `#12` のような番号が付いています。人に「#12 のことだけど」と口で指すための札で、検索欄に `12` や `#12` と打てばそのノードが出ます。

## 2. 入る

開いたときに「どこから手を付けるか」を決めるための画面です。

### データの場所を決める

初めて起動すると、**データを置くフォルダ**を聞かれます。空のフォルダを選べば新しく始まり、既に Sirube のデータが入ったフォルダを選べばその続きが開きます。空のフォルダを初めて開いたときは、チュートリアルが自動で始まります。

一度選んだフォルダは覚えていて、次からはそのまま開きます。別のフォルダに切り替えるときは、ヘッダーのフォルダ名を押して「**別のフォルダを開く**」を選びます。

### 前回の続きから開く

閉じたときに見ていた場所（一覧か、どのノードのグラフか、地図か）を覚えていて、次に開くとそこから始まります。戻りたければ、サイドバーの「今やれること」を押せばいつでも最初の一覧です。

### 今やれること

必要なものが全部揃っていて、**今すぐ手を付けられるもの**の一覧です。起動直後はここが出ます。

| 列 | 意味 |
|---|---|
| 番号 | `#12` の札 |
| 名前 | ノードの名前 |
| 合流 | 何か所から必要とされているか。2以上のときだけ出る |
| 期限 | 期限があるものだけ。破線の枠は、上のノードから伝わってきた期限（→ 6. 進める） |
| 目的 | どのゴールの下にいるか |

- **並びは合流の多い順**です。片付けたときに進むものが多い順、と読めます。見出しを押しても並べ替わりません——並びは構造から出る優先順位だからです
- 行の左端の色は、属しているゴールの付箋の色です
- 行を押すと、そのノードがいる場所のグラフが開きます
- 待ち合って一周しているせいで何も動けないときは、その一周が一覧の上に出ます（→ 7. 整える）

### 最近の変更

ファイルが書き換わった順に、新しいものから30件並びます。**しばらく空けて開いたとき「何を動かしていたか」を思い出すため**の一覧です。

- 自分が触ったものだけでなく、達成に連動して一緒に書き換わったもの、AI やほかのツールが書いたものも並びます
- 見出しを押すと、番号・目的・状態・更新日で並べ替えられます。もう一度押すと逆順。並べ替えは覚えておらず、開き直すと新しい順に戻ります

### 目的の一覧

サイドバーの「目的」には、**地図に出ているゴール**が並びます（→ 5. 俯瞰する）。

- 数字は「達成した数／全体」
- 押すとそのゴールのグラフが開きます
- 今見ている場所に一番近いゴールの行が光ります
- 終わりのない目的（地図から外した根）は、ここには出ません

### 検索

ヘッダーの検索欄に打つと、真ん中が検索結果に変わります。

- **名前と本文**の両方から探します。全角半角、大文字小文字の違いは気にしなくていい
- `12` や `#12` と打つと、その番号のノードが一番上に出ます
- 名前で当たったものが、本文で当たったものより上に並びます
- 結果の各行の下に、**隣のノード**（これが必要／これを待っている／構成要素／属する先）も出ます。言葉を思い出せなくても、近くのものから辿り着けます
- 状態が混ざっているときは「状態」の列が出ます
- 検索欄を空にすると「今やれること」に戻ります

## 3. 分解する

目的から「それには何が必要か」を下ろしていく章です。Sirube の中心の操作です。

### 目的を作る

サイドバーの「目的」の横の **＋** を押し、名前を書いて「作成」。どこからも必要とされていないノードは、自動的に目的（ゴール）になります。

同じ名前のノードは作れません（「◯◯は既にあります」と出ます）。

### 前提と中身の見分け方

「何が必要か」を足すとき、**前提**として足すか**中身**として足すかを選びます。迷ったら、この1問で決まります。

> **必要なものが全部揃ったあと、まだ自分でやることが残っているか？**

| 答え | 選ぶもの | 例 |
|---|---|---|
| 残っている | **前提** | 引っ越し — 家もお金も揃っても、引っ越し作業そのものが残る |
| 残っていない | **中身** | 「Aさんの担当分」— 中のタスクが全部終われば、担当分としてやることは無い |

違いは、**済んだことの伝わり方**です。

- **前提**: 上を達成にすると、その前提も「済んでいたはず」として一緒に達成になる（下へ伝わる）
- **中身**: 中身が全部揃うと、上も自動で達成になる。中身を1つ未達に戻すと、上も未達に戻る（上へ伝わる）

中身を持つノードは、中身が揃うまで「今やれる」になりません。上には固有の作業が無いからです。

### 分解する

詳細パネルの「**分解する**」を押します（グラフのノードの右クリックや、パンくずの頭の **＋** からも開けます）。

- 上のタブで「**前提**」か「**中身**」を選ぶ
- **1行に1つ**書く。Enter は改行、**Ctrl+Enter** で追加
- **既にある名前を書くと、新しく作らずにそのノードに繋がります。** 下見に「うち ◯件は既存に繋ぎます」「◯件は既に前提です」と出るので、押す前に分かります
- 書きかけのまま前提と中身のタブを切り替えても、書いた内容は残ります

達成済みのノードに未達の中身を足すと、「**未達に戻す**」か「**そのまま**」かを聞かれます。中身がまだ終わっていないのに上が達成のままだと、食い違うからです。

### ここに足す（＋）

真ん中のパンくずの頭にある **＋** は、**今選んでいるノード**の「分解する」を開きます。グラフで焦点ではない下のノードを1回押して選んでから ＋ を押せば、そのノードに足せます。何も選んでいないときは「まとめて書く」が開きます。

既にあるノード同士を繋ぎたいときも、ここから相手の名前を書けば繋がります。

### まとめて書く

構造をまとめて書き下す書き方です。サイドバーの ＋ で開く画面の「**まとめて書く**」タブか、グラフの何もないところの右クリック →「まとめて追加」で開きます。

| 書き方 | 意味 |
|---|---|
| `X -> Y` | X には Y が**前提**として必要 |
| `X -> Y -> Z` | X には Y、Y には Z が必要（鎖になる） |
| `X -> [Y]` | Y は X の**中身** |
| `X -> [Y] -> [Z]` | Y も Z も X の中身（兄弟になる） |
| `,` | 式の区切り |

```
引っ越し -> 引っ越し先の家 -> 不動産に行く,
引っ越し -> お金を貯める
```

- 同じ名前は同じノードになります。既にある名前なら、そのノードに繋がります
- 押す前に「◯件を新しく作り、◯件は既存に繋ぎます」と下見が出ます。書き方が間違っているときは、どこが悪いかが出ます

### 近道を外す

兄弟として並べていたものの間に、あとから順序があると分かって繋ぐと、上から直接の線が要らなくなることがあります。

```
引っ越し → 家 → 不動産に行く
引っ越し → 不動産に行く        ← 家を経由して届くので、要らない
```

このとき「**直接の繋がりが要らなくなりました**」と出て、「外す」か「そのまま」かを聞かれます。残しても状態は壊れませんが、2か所から必要とされている（合流）ように見えて、一覧の並びが実際より前に来ます。

### 間に差し込む

グラフの線を押すか、右クリック →「**間にノードを差し込む**」。2つのノードの間に新しいノードを1つ入れます。元の線は外れ、鎖が1段伸びます。

### 外す

繋がりだけを切ります。ノード自体は消えません。

- グラフのノードを右クリック →「**「◯◯」から外す**」。親が複数いれば、親ごとに1行ずつ出ます
- グラフの線を右クリック、または詳細パネルの「これを待っている／属する先」の行を右クリックしても出ます
- **最後の親から外すと、そのノードは目的として一覧に出ます。** メニューに「（目的として一覧に出ます）」と書いてあるときがそれです
- 地図の上では出ません（地図の線は間を畳んでいるので、どの親から外れるのかが画面と一致しないため）

### 削除

詳細パネルの一番下「その他」→「このノードを削除」→「削除する」。

- 下にあったノードのうち、ほかに親がいないものは目的として一覧に出るようになります。削除の前に件数が出ます
- 繋がっていた線も一緒に片付きます

### 戻す

ヘッダーの「**戻す**」で、直前の1手だけ戻せます。戻せるものがあるときだけボタンが出ます。

- 戻せるのは、削除・外す・近道を外す・一緒に書き換わった達成（→ 6. 進める）
- **1手だけ**です。次に何か操作すると、戻せる対象はそれに入れ替わります
- 戻す前にファイルが外で書き換わっていたら、戻しません

外したあとで戻したくなったら、「まとめて書く」に `親 -> 子` と書いても繋ぎ直せます。

### 改名

詳細パネルの名前の横の鉛筆を押します。ほかのノードからの繋がりは切れません。ほかのノードと同じ名前にはできません。

### 名前の付け方のコツ

- **終わりのある形にする。** 「ブログ」のような名詞だけだと、達成が何を意味するのか分からなくなります。「ブログを開設する」「ブログの方針を決める」のように、終わったと言える形にします
- **自分で終わらせられないもの**（在庫待ち・返事待ち）は、今日終わる部分を前提として切り出します。「中古のカメラを買う」→ 前提に「巡回先をまとめる」。なぜ待っているのかは、メモに1行書いておきます
- 2つの目的にまたがるものは、ノードを分けずに1つのまま、両方から繋ぎます。それが合流になります

## 4. 辿る

目的から末端まで、グラフで行き来する章です。

### グラフに描かれるもの

グラフは「**今いる地点**（焦点）」から見た周りだけを描きます。全体を1枚には描きません。

- 真ん中の上に焦点のノード、その下に必要なものが並ぶ
- **前提**は鎖の先まで描く（なぜ今これがやれるのかを追えるように）
- **中身**は1段下までだけ描く。その下を見るには潜る
- 上のノード（このノードを必要としている側）はグラフには描かず、詳細パネルの「これを待っている／属する先」に出る

### 印の見方

ノードは丸い印と、その下の名前で描かれます。グラフの左下の丸いボタンにマウスを乗せると凡例が出ます（押すと出したままにできる）。

| 見た目 | 意味 |
|---|---|
| 印の色 | 状態（今やれる／前提待ち／達成済み／待ち合って一周している） |
| 実線 | これが必要（前提） |
| 破線 | これで構成（中身） |
| 印を囲む弧 | 下にあるものの進み具合 |
| 印の横の数字 | 何か所から必要とされているか（合流） |

数字の詳しい値は、印にマウスを乗せると出ます。ノードにマウスを乗せると、そのノードの線が強調されます。

### 選ぶ・潜る・戻る

| 操作 | 起きること |
|---|---|
| ノードを1回押す | **選ぶだけ**。右の詳細パネルがそのノードになる。画面は動かない |
| 選んでいるノードをもう1回押す | そのノードへ**潜る**（焦点になる）。下に何も無いノードは潜らない |
| 焦点のノードを1回押す | 選ぶだけ |
| 焦点を選んでいる状態でもう1回押す | **1つ上へ戻る** |
| パンくずの名前を押す | 辿ってきた道のその地点へ戻る |

1回目で選ぶだけにしてあるのは、詳細を見たくて押しただけで画面が移ってしまわないようにするためです。

### 下にあるものを覗く

下を持つノードにマウスを乗せると、その下に積まれているもの（さらに下を持つものだけ）が一覧で出ます。一覧の名前を押すと、途中を飛ばしてそこへ1回で移れます。

### 動かす・拡大する

- **ドラッグ**で動かす
- **ホイール**（トラックパッドならピンチ）で拡大・縮小。マウスの下にある点を中心に拡大する
- 動かしたり拡大したりすると、隅に倍率（`120%` など）が出ます。押すと元の表示に戻ります

表示の位置と倍率は、同じ場所にいる間は保たれます。別のノードへ潜ると初期の表示に戻ります。

### 詳細パネルで上へ辿る

グラフは下向きしか描かないので、上へ辿るのは詳細パネルの役目です。

- **これを待っている** — このノードを前提にしている上のノード
- **属する先** — このノードを中身にしている上のノード

名前を押すとそこへ移ります。親が複数いる（合流している）ノードでは、パンくずは自分が辿ってきた道しか持たないので、ほかの親へはここから行きます。

### メモ

ノードの本文です。既定は読む表示で、「**編集**」を押すと書けます。書き終えて欄の外を押すと保存されます（「閲覧」で読む表示に戻る）。メモを右クリックすると「編集する」「メモをコピー」が出ます。

読む表示で整えて描かれるのは次の書き方です。それ以外は書いたままの文字で出ます。

| 書き方 | 表示 |
|---|---|
| `# 見出し`（`##` `###` まで） | 見出し |
| `- 項目` | 箇条書き |
| 2つのアスタリスクで囲む | 太字 |
| バッククォート1つで囲む／3つの行で挟む | 等幅（コード） |
| `> 引用` | 引用 |
| 縦棒で区切った行と、その下の区切り行 | 表 |
| `---` | 区切り線 |
| `https://…` | リンク（ブラウザで開く） |

メモはノードのファイルの本文そのものなので、Obsidian やエディタで開いても同じ内容が見えます。

### 作成日と更新日

メモの下に小さく出ます。更新日は、そのノードのファイルが最後に書き換わった日です。自分が触った日とは限りません（達成に連動して書き換わった、AI が書いた、なども含む）。

## 5. 俯瞰する

グラフは1段ずつ潜る道具です。この章は、**一度に広く見る**ための2つの見え方と、その見え方に何を載せるかの話です。

### 俯瞰（ここから下を一息に）

グラフを見ているときに、パンくずの右端の「**俯瞰**」を押します。**今いるノードの下にある「今やれること」**が、一覧で全部出ます。

- 目的で押せばその目的の下全部、潜った先で押せばその枝の下だけ
- パンくずには「◯◯ の配下」と出ます
- 行を押すと、そのノードを焦点にしたグラフが開きます。パンくずには俯瞰していた目的が残るので、そこから戻れます
- 右端の「グラフ」で元のグラフに戻ります
- 全部が同じ目的の下なので、目的の列は出ません

### 地図（ゴールだけを浮かび上がらせる）

パンくずの右端の「**地図**」を押すと、**ゴールだけを残して、間のノードを畳んだ図**になります。

- 地図は1枚です。どこから上がっても同じ図で、上がる前にいた場所に印が付きます
- ゴールからゴールへの線の上の数字は、**間に畳んだノードの数**です
- 印の横の数字は、いくつのゴールがそこを通るかです
- 地図ではノードを押すと選ぶだけです。そのゴールのグラフへ降りるには、右端の「**グラフ**」を押すか、右クリック →「**グラフで開く**」
- 地図の上では「外す」は出ません（→ 3. 分解する）

### 何がゴールになるか

- **どこからも必要とされていないノード**は、自動的にゴールです
- 途中にあるノードも、詳細パネルの「その他」→「**地図に出す**」でゴールにできます。1つの目的の下が深くなりすぎたとき、途中の段を入口にするための機能です
- ゴールは「その他」→「**地図から外す**」で外せます。一生続くような**終わりのない目的**を根に置いているときに使います。外すと地図とサイドバーから消えますが、繋がりや状態はそのままです

**根を地図から外すときの注意**: 外しても、その下のノードは自動ではゴールになりません。下に地図へ出したいものがあるなら、先にそちらを「地図に出す」にしておいてください。そうしないと、地図からその一帯がまとめて消えます。

目安は「**半年空けて開いたとき、そこから道を思い出したいか**」です。作業の束のようなものをゴールにすると、地図が作業で埋まってしまいます。

### 付箋

ゴールには色の付箋を貼れます（黄・橙・桃・紫・青・緑）。詳細パネルの「付箋」から選び、同じ色をもう一度押すと外れます。

貼った色は、サイドバーの目的の行と、「今やれること」の行の左端に出ます。どのゴールの下の作業か、色で見分けられます。ゴール以外のノードには貼れません。

### 進み具合の出方

| 場所 | 出方 |
|---|---|
| サイドバーの目的 | 達成した数／全体 |
| 詳細パネル | バーと数 |
| グラフの印 | 印を囲む弧 |

**終わりのない目的**（地図から外した根）では、割合に意味がないので、分数やバーを出さずに「**達成 ◯件 ／ 全 ◯件**」と2つの数を並べます。全体の数は、どれだけ広がったかを見るために残してあります。

## 6. 進める

終わったものを「達成」にして、道を先へ進める章です。

### 達成にする

詳細パネルの「**達成にする**」を押します（グラフのノードの右クリックからも）。押すと、そのノードを必要としていた上のノードのうち、ほかに揃っていないものが無いものが「今やれる」に変わります。

達成済みのノードでは、同じ場所が「**達成を取り消す**」になります（右クリックでは「未達に戻す」）。

### 一緒に書き換わるもの

達成は1つのノードだけでは終わらないことがあります。繋ぎ方（→ 3. 分解する）に沿って、周りも一緒に書き換わります。

| したこと | 一緒に起きること |
|---|---|
| 達成にする | その**前提**も、鎖を遡って全部達成になる（後が終わったなら、前も終わっていたはず） |
| 達成にする | **中身**が全部揃った上のノードが達成になる（上に固有の作業は無いので） |
| 取り消す | そのノードを必要としていた**上のノード**が、前提でも中身でも全部未達に戻る（土台が崩れたなら、上も本当は終わっていない） |

取り消しても、下の前提には触りません。1つ戻したからといって、その前にやったことが無かったことにはなりません。

### 書く前の下見

押したノード以外の達成が変わるときは、**書き換える前に一覧が出ます**。「前提を埋める」「達成を戻す」「親を達成に」と、何がなぜ変わるのかが名前で並びます。

- 選べるのは「実行」か「キャンセル」の2つだけです。1件だけ外すことはできません
- **覚えのないものが並んでいたら、繋ぎ方を疑ってください。** 「どれか1つでいい」ものを前提として繋いでいると、使わなかった方まで達成になります。どれか1つでいいものは前提ではなく選択肢なので、繋がずにメモへ書きます
- 中身が揃って上が達成になるだけのときは、下見は出ません（末端を1つ潰すたびに確認が出るのを避けるため）

一緒に書き換わった分は、ヘッダーの「**戻す**」でまとめて元に戻せます（→ 3. 分解する）。

### 期限

期限は、**外の都合で本当に日付が決まっているもの**にだけ付けます。自分で決めた目安の日付は付けません。

期限は下へ伝わります。「引っ越し」が3月31日なら、その前提の「引っ越し先の家」も、そのまた前提の「不動産に行く」も、暗黙に3月31日までです。

- 伝わった期限は、「今やれること」の期限の列に**破線の枠**で出ます。マウスを乗せると、どこから来たかが出ます
- 詳細パネルでは、期限の下に「**「引っ越し」に間に合わせる**」と、どこから来たかが文字で出ます
- 自分の期限の方が早ければ、そちらが効きます（詳細パネルに両方出ます）
- 達成済みのノードは、期限を伝えも受け取りもしません
- 期限が近づいても、催促や警告は出しません

### 合流を先に片付ける

「今やれること」は合流の多い順に並んでいます（→ 2. 入る）。合流が2以上のノードは、片付けると**一度に複数の道が進みます**。何から手を付けるか迷ったら、上から取れば構造が勧める順になります。

### 自分で終わらせられないもの

返事待ち・在庫待ちのように、前提は済んでいるのに終わらせられないノードは、「今やれること」に出続けます。これは分解が足りない合図です。今日終わる部分を前提として切り出し、待っている理由をメモに1行書きます（→ 3. 分解する「名前の付け方のコツ」）。

## 7. 整える

構造が食い違ったり、動けなくなったりしたときに直す章です。

### 状態の4つをもう一度

| 状態 | 意味 | することの目安 |
|---|---|---|
| 今やれる | 必要なものが全部揃っている | やる |
| 前提待ち | まだ揃っていないものがある | 下を片付ける |
| 達成済み | 済んだ | なし |
| 待ち合って一周している | お互いを待っていて動けない | 割る（下で説明） |

状態はファイルに書かれておらず、開くたびに構造から計算し直します（→ 0. 考え方）。

### 待ち合って一周している

ノード同士がお互いを必要としていて、一周して戻ってくることがあります。

```
実績を作る → 案件を取る → 実績を作る
```

これは**エラーではなく、分解が足りない合図**です。待ち合って一周するのは、1つの名前に2つの違うものが混ざっているときです。上の例では「案件を取る」の中に「実績が要る案件」と「実績が要らない案件」が同居しています。

**やることは「線を切る」ではなく「ノードを割る」です。**

```
大きい案件を取る → 実績を作る → 小さい案件を1件やる → 知人に声をかける
```

割ると一周が消え、しかも今日やれること（知人に声をかける）が1つ生まれます。

- 一周のせいで何も動けないときは、「今やれること」の上に一周が並んで出ます。名前を押すとそのノードを選び、「**割る**」で分解が開きます
- 一周の上にいるノードの詳細パネルにも「待ち合って一周しています」と出ます
- どうしても割れない本当の相互依存なら、どれか1つを達成にして一周を抜けて構いません（「不完全なまま始める」という表明）。ただし先に割れないか試してください

**中身どうしの一周**（AはBでできていて、BはAでできている）は、割るのではなく、どれかの中身の繋がりを外します。

### 自動解決

ヘッダーの「**自動解決**」は、食い違いを直す提案です。提案があるときだけ、件数付きで出ます。押すと一覧が出て、確かめてから実行します。

**ファイルの更新時刻が新しい方を「最新の意図」として扱います。** 出てくる提案は次のとおりです。

| 提案 | 起きていること |
|---|---|
| 前提を埋める | 達成済みなのに前提が未達。達成した側の方が新しい |
| 達成を戻す | 達成済みなのに前提が未達。前提の方が新しい（前提を未達に戻したのが後） |
| 親を達成に | 中身が全部揃っているのに、上が未達 |
| 達成を戻す（中身） | 中身に未達があるのに上が達成。未達の中身の方が新しい |
| 空ノード作成 | 繋がりの先のノードが見つからない |

中身が未達で上が達成のとき、**上の方が新しければ何も提案しません**。到達した達成は記録として残す、という扱いです。

自動では直せず、**判断が必要**として別に並ぶものもあります。

| 見出し | することの目安 |
|---|---|
| 待ち合い | 割る（上で説明） |
| 内包の待ち合い | どれかの中身の繋がりを外す |
| 表記ゆれ | よく似た名前のノードが複数ある。どちらかに寄せるか、名前を分ける |
| 決められない | 達成と未達を行き来してしまう。どちらが正しいかを手で決める |
| 時刻が近すぎる | どちらが新しいか分からない。手で決める |

「**ファイルの問題**」として、読めなかったファイルも並びます。これはアプリの中からは直せないので、そのファイルを開いて直します（AI に頼むのが早い → 8. 渡す）。

### 外でファイルが書き換わったとき

アプリはデータのフォルダを見張っています。**AI やほかのツールがファイルを書き換えると、画面は自動で追いつきます。**

- 達成の下見や確認を開いている間に外で書き換わったら、書き込まずに「もう一度押してください」と出ます。見せた内容と違うものを書かないためです
- 「戻す」も同じで、外で書き換わった分は戻しません
- 外で `satisfied` を直接書き換えた場合、前提や中身は一緒に書き換わりません。食い違いは自動解決が拾います

### 番号が重なったとき

2台で別々に作ったノードを合わせると、同じ番号が2つできることがあります。アプリは読み込むときにこれを見つけ、**後から作られた方に新しい番号を振り直します**。自分で直す必要はありません。

## 8. 渡す

データを外へ持ち出す、AI に触らせる、控えを取る、の章です。

### データの形

選んだフォルダの中身はこうなっています。

| 場所 | 中身 |
|---|---|
| `nodes/` | **これが全部**。ノード1つが Markdown ファイル1つ |
| `00_Sirube_MOC.md` | 入口。目的の一覧と、それぞれの今やれること |
| `goals/` | 目的ごとの入口 |
| `90_達成済み.md` | 達成したものの一覧 |
| `AGENTS.md` | AI 向けの説明書 |

`nodes/` 以外はアプリが起動のたびに作り直す**生成物**です。編集しても上書きされ、消しても次に開けば戻ります。

ノードのファイルはこういう形です。

```
---
name: 確定申告
number: 9
satisfied: false
requires:
  - 01M1DR2XM4BSDZTH8C12FMC0YC  # 領収書整理
contains: []
due: 2027-03-15
---

去年は freee で出した。今年は医療費控除も入れる。
```

ファイル名は意味を持たない ID です。名前は中の `name` にあるので、改名しても繋がりは切れません。

### Obsidian やエディタで読む

フォルダはそのまま Obsidian の Vault として開けます。入口のファイルからリンクで各ノードへ辿れ、スマホの Obsidian からも読めます。

**書き込むのはアプリからにしてください。** アプリで押すと一緒に書き換わるもの（→ 6. 進める）が、ファイルを直接書くと書き換わりません。書き込む口が増えるほど、食い違いの出方が散らかります。

### AI に読み書きさせる

Sirube のアプリに AI の機能はありません。データがただの Markdown なので、Claude Code や Cursor のような AI エージェントにフォルダを触らせれば、それがそのまま連携になります。

アプリは起動のたびに、今開いているフォルダの場所を次のファイルに書き出しています。

```
%LOCALAPPDATA%\jp.motimotinotch.sirube\vault-path.txt
```

1. **場所を教える。** AI には「上のファイルを見て」と言えば、フォルダまで辿り着きます
2. **説明書を読ませる。** フォルダの中の `AGENTS.md` を読むように言います。前提と中身の見分け方など、ファイルを見ただけでは分からない決まりが書いてあります
3. **頼む。** 目的の分解、止まっているところの洗い出し、メモの整理など

AI が書いたものは、アプリが自動で画面に出します。

**達成は AI に書かせず、アプリで押してください。** ファイルで達成にすると前提が一緒に書き換わりません（やってしまっても、自動解決が辻褄を合わせます）。

### 控えを取る（git）

フォルダごと git で管理できます。生成物を除いておくと、差分が「どのノードをどう動かしたか」そのものになります。

```
/00_Sirube_MOC.md
/90_達成済み.md
/goals/
```

（上を `.gitignore` に書く）

アプリは git を操作しません。コミットは自分で（または AI に頼んで）します。

### 別の PC で使う

フォルダを git やクラウドの同期で持っていき、向こうのアプリで「**別のフォルダを開く**」から選べば続きが開きます（→ 2. 入る）。

- 2台で同じノードを同時に書き換えると、git の衝突になります。どちらが正しいかを決めて直してください
- 番号の重なりはアプリが直します（→ 7. 整える）

### キー操作

| キー | 場面 | 起きること |
|---|---|---|
| Ctrl+Enter | 分解する／まとめて書く | 追加する |
| Enter | 目的を作る／間に差し込む | 作る |
| Enter | 改名 | 確定する |
| Escape | 改名 | やめる |
| Escape | 確認・メニュー | 閉じる（キャンセル） |
| ホイール | グラフ・地図 | 拡大・縮小 |
| ピンチ | グラフ・地図（トラックパッド） | 拡大・縮小 |

達成の確認では、開いたときに「キャンセル」が選ばれています。勢いで Enter を押しても書き込まないためです。

### 用語集

| 言葉 | 意味 |
|---|---|
| ノード | 1つの「やること」または「目的」。ファイル1つ |
| 目的（ゴール） | 地図に出ているノード。どこからも必要とされていないものは自動でなる |
| 前提 | 揃ったあとも自分でやることが残る「必要なもの」 |
| 中身 | 全部揃えばそれで終わる「必要なもの」 |
| 今やれる | 必要なものが全部揃った状態 |
| 前提待ち | まだ揃っていないものがある状態 |
| 待ち合って一周している | お互いを必要としていて動けない状態 |
| 合流 | 複数の場所から必要とされていること。片付けると一度に複数が進む |
| 焦点 | グラフで今いる地点 |
| パンくず | 辿ってきた道 |
| 俯瞰 | 今いるノードの下の今やれることを一覧で見る |
| 地図 | ゴールだけを残して間を畳んだ図 |
| 付箋 | ゴールに貼る色 |
| 伝わった期限 | 上のノードの期限が、下へ暗黙に伝わったもの |
| 自動解決 | 食い違いを更新時刻で直す提案 |
| 生成物 | アプリが作り直すファイル。`nodes/` 以外 |

### よくある質問

**優先度やタグを付けたい**

付けられません。「今やれること」の並び（合流の多い順）が優先度の代わりで、分類は繋ぎ方（どの目的の下にいるか）が代わりをします。同じことを2通りで書けると、ノードを作るたびにどちらで書くかを考えることになり、分解が止まるためです。

**「今やれること」が空になった**

待ち合って一周しているせいなら、その一周が一覧の上に出ます。「割る」から直します（→ 7. 整える）。出ていなければ、未達のものが全部「前提待ち」か、全部終わっています。前提待ちの一番下に、まだ分解していないものが無いか見てください。

**待っているだけのものが「今やれること」に居座る**

返事待ちや在庫待ちのノードは、今日終わる部分を前提として切り出し、待っている理由をメモに書きます（→ 3. 分解する「名前の付け方のコツ」）。

**押したら覚えのないものまで達成になった**

ヘッダーの「戻す」で元に戻せます。そのあと、繋ぎ方を見直してください。「どれか1つでいい」ものを前提として繋いでいると、こうなります（→ 6. 進める）。

**間違えて削除した**

すぐなら「戻す」で戻せます。1手だけなので、次の操作をする前に。

**Obsidian で直接書き換えてもいい？**

読むのはどこからでも構いませんが、書くのはアプリからにしてください（→ 8. 渡す）。書いてしまった場合、食い違いは自動解決が拾います。

**チュートリアルをもう一度見たい**

ヘッダーの「使い方」を押すと、このマニュアルの先頭に「チュートリアルをもう一度」があります。
